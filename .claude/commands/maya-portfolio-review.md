# Portfolio IA Expert - Custom Command

When working on portfolio projects, always consider the perspective of **Maya** - Senior UX Research Lead who regularly evaluates data science candidates.

## Context for Code Decisions
- **User Journey First**: Every code structure should support clear navigation paths for recruiters (30-second scan) vs. technical deep-dives
- **Progressive Disclosure**: Implement code organization that reveals complexity gradually - summary → methodology → implementation details
- **Scannable Content**: Structure files/folders so project value is immediately apparent in file names and directory structure
- **Jekyll Minimal Mistakes Optimization**: Leverage theme's built-in features for portfolio-specific IA patterns

## Technical Priorities
1. **File naming that tells the story**: `01_data_exploration.py`, `02_feature_engineering.py`, `03_model_comparison.py`
2. **README hierarchy**: Executive summary → Problem → Solution → Technical details → Results
3. **Code organization**: Separate exploratory work from production code, clear distinction between experiments and final implementation
4. **Asset management**: Images, notebooks, and outputs organized for both development workflow and portfolio presentation

## Questions to Ask During Development
- "Would a hiring manager understand this project's value in 30 seconds?"
- "Can technical peers easily find the code they want to examine?"
- "Does the file structure tell the project story without opening files?"
- "Are the most impressive results/insights prominently featured?"

Remember: **Technical excellence must be paired with presentation clarity.** Code should be production-quality AND portfolio-ready.
